# Using the UI

How to drive the frontend, which database answers which questions, and what
you are actually looking at.

---

## Start it

```bash
ollama serve          # separate terminal — needed for the real agent
ollama pull qwen2.5-coder:3b

python server.py      # then open http://localhost:8000
```

First load takes a few seconds: React, Babel and Tailwind come from CDNs and
the JSX is compiled in the browser.

---

## 1. Connect a dataset

Nothing is connected at startup — deliberately. You'll see an amber panel with
one-click buttons.

**This matters more than it looks.** The tools used to default to a demo
database, so a failed upload still produced confident answers about data nobody
had chosen. Now no dataset means no answers.

| database | contains | tables |
|---|---|---|
| **`analytics`** | sales demo — orders, customers, products, regions | 4 |
| `chinook_1` | a music store — Album, Artist, Track, Invoice | 11 |
| `college_2` | a university — student, course, instructor, department | 11 |
| `formula_1` | motorsport — races, drivers, constructors, results | 13 |

**Pick `analytics` for a demo.** Every preset question is written against it,
and its numbers are seeded so the answers are checkable.

The other three are the Spider benchmark databases the critic was trained and
evaluated on. `chinook_1` is the holdout — the one the critic had never seen
until notebook 06.

## 2. Choose how it runs

The **Router Mode** control picks between two genuinely different engines. This
is worth understanding before you demo, because they answer the same question
in completely different ways.

### `simple` — the real ReAct agent (layer B)

Calls `run_agent()`. An LLM reads the schema, writes SQL, sees what came back,
and decides what to do next. Nothing is scripted:

```
Thought:  I need to see what tables exist
Action:   get_schema {}
Obs:      orders(order_id, customer_id, sales, profit, date, region) ...
Thought:  I can sum sales grouped by region
Action:   run_sql {"query": "SELECT region, SUM(sales) ... GROUP BY region"}
Obs:      5 rows. [{"region": "North America", "total_sales": 180500.0} ...]
Thought:  North America is highest
Action:   final_answer
```

**Needs Ollama running.** Takes 5–20 seconds. It can fail, and that is the
point — the trajectory shows it recovering from errors.

This is the path your critic scores.

### `full` — the orchestration graph (layer D)

Calls `run_graph_to_record()`, which routes by keyword to a prepared SQL query.
Fast and reliable, and **the SQL does really execute** — the $180,500 comes from
the database, not from a constant.

But it only handles questions phrased close to the presets. Ask something new
and it falls through.

### `auto`

A trained classifier picks between them. Fine for a demo, but say which one it
chose — the answer's provenance depends on it.

**For your mentor: use `simple`.** `full` looks smoother and shows less of your
work.

## 3. Ask something

### On `analytics` — use the preset buttons

```
Which region had the highest total sales in 2023?
What is the total profit generated by Enterprise customers in 2023?
Which product category produced the highest total revenue across all years?
Analyze sales by region and create a bar chart
Calculate statistical correlation between sales and profit
```

Verified answer for the first: **North America, $180,500** — then Asia
$135,000, Europe $125,000, Middle East $85,000, Latin America $58,000.

### On `chinook_1` — type your own

The presets won't work here; there is no `orders` table. Ask music questions:

```
How many albums are there?                          -> 347
What are the titles of albums by the artist AC/DC?
Find the names of artists that do not have any albums.
How many tracks are longer than 5 minutes?
```

These are close to the 30 holdout questions, so the agent's behaviour here is
the behaviour that was measured.

### On `college_2`

```
Which department has the lowest budget?
How many students are advised by each instructor?
List the courses with more than two prerequisites.
```

## 4. Where to look

**Query Studio (main panel)** — the question box, router mode, and the Run
button. The button stays greyed out until a dataset is connected.

**Agent Trajectory** — the interesting part, and the one to show a mentor. Every
step expands to reveal:

- **Thought** — the model's stated reasoning
- **Action** — the tool and its arguments, including the exact SQL
- **Observation** — what came back, or the error

Errors are worth pausing on. A run that hits `no such column: Name` and then
fixes itself is a better demo than one that works first time, because it shows
the loop doing what it exists to do.

**Final Answer** — green banner at the top once the run terminates.

**Charts tab** — populated only when a run produces a chart. It starts empty;
it used to ship three fabricated charts stamped "Just now", which is why the
page looked busy before you had asked anything.

**Trajectories tab** — the 1,700 logged runs from
`data/trajectories/*.jsonl`. Click one to replay it step by step. Useful for
showing failure modes without waiting for a live failure.

**ML Metrics tab** — the tool classifier and complexity router evaluations.

## 5. A demo that shows the work

1. **Start disconnected.** Point out that nothing runs until a dataset is
   chosen, and that this is deliberate: no data, no answers.
2. **Connect `analytics`.** The Run button becomes live.
3. **Set mode to `simple`** and ask *"Which region had the highest total sales
   in 2023?"*
4. **Walk the trajectory** — schema inspection, then SQL, then the answer. This
   is the ReAct loop.
5. **Switch to `chinook_1`** and ask *"How many albums are there?"* Same agent,
   a database it was never trained on, 347. That's the generalisation result
   from notebook 06 made visible.
6. **Open the Trajectories tab** and find a failed run. Show it looping or
   erroring — then explain that the critic predicts this at step 0 with 59%
   recall, and stopping those runs saves a third of the compute.

Step 6 is the one that connects the UI to the research.

## When something goes wrong

| symptom | cause |
|---|---|
| Run button greyed out | no dataset connected — pick one |
| "No dataset provided" | same, or the connection was cleared |
| Query hangs 30s then fails in `simple` | Ollama isn't running (`ollama serve`) |
| `no such table: orders` on chinook | preset question against the wrong database |
| Blank page | JSX error — check the browser console (F12) |
| `404 /favicon.ico` in the server log | harmless, there is no icon file |

**Before demoing, run:**

```bash
python scripts/smoke_test.py --with-agent
```

Twenty-six checks plus one real end-to-end query. If that is green, the demo
will work.
